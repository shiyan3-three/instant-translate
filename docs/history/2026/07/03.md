# 2026-07-03 开发记录

## 集成前可靠性修复

- 翻译请求改为两阶段提交：API 生成结果时不修改 Agent Session，只有请求仍为当前版本时才记录并持久化。
- 去除会吞掉否定词、数字和时态变化的 trigram 模糊去重，只跳过完全相同的 OCR 文本。
- Agent 会比较语言、Prompt hash、Fast 模型与 Thinking 模型元数据；配置变化后自动重建。
- Session JSON 改为临时文件原子替换，并增加读写锁；删除选区时可同步清除对应持久 Session。
- Thinking/Pro 请求提高超时与 token 预算；日志不再记录模型正文预览。
- 后台翻译和 OCR 的未知异常不再静默丢失，回调异常也不会导致重复回调。

## OCR 与选框

- PaddleOCR 初始化与识别通过同一把锁串行执行，避免多组选区并发访问预测器。
- 模糊稳定 OCR 会延续原有 2 秒稳定窗口；单次空 OCR 不再立即覆盖上一条译文。
- 截图会选择选区所在显示器，并把虚拟桌面坐标换算成屏幕局部坐标。
- 选框描边改画在采集区域外侧，不再依靠轮询隐藏窗口，因此不会重新引入闪烁。
- 翻译框或 OCR 窗口如果与采集区域相交，会恢复到自动停靠位置。

## 实测回归后的约束与生命周期修复

- Compiled Prompt 新增同名 `.policy.json` sidecar。用户继续输入自然语言要求，Thinking 模型可提出结构化 Policy；本地只接受白名单规则和经过类型、范围、长度校验的参数，不执行模型生成的代码、命令或正则。
- 旧 Prompt 没有 sidecar 时，会从用户确认的原始约束安全回建 Policy；当前“纯平假名、软件术语方括号、至少双空格”规则无需用户重新保存即可生效。
- 本地输出链按 Policy 执行片假名转平假名、长音转换、禁用标点清理、空格宽度归一化，并校验字符集、术语包裹、空格、长度、换行、大小写、保留项和固定替换。
- 严格字符规则下不再把 `API`、数字等源文本强制原样恢复，也不再自动追加“无法转换时保留原文”这一条会削弱用户硬约束的说明。
- 翻译去重拆分为“正在请求”和“已经成功显示”：失效或失败只清除 pending，只有成功结果才能成为 committed，编辑模式打断后相同 OCR 可以重新提交。
- 删除选择框只销毁运行时 Agent，不再删除持久 Session；显式清除接口仍保留。
- PaddleOCR 后台预热会实际执行一次小型推理，并按语言去重，从而把首次推理冷启动移出第一次真实选区识别。
- 本轮仍未集成 `RETRIEVED_POLICY`、启动 Pro Policy 或新的 Agent 记忆架构。
