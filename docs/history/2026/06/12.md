## Bug 修复：API 返回空翻译（已解决）

### 问题根源

DeepSeek thinking 模式下，**翻译结果全部放在 reasoning_content 字段，content 字段为空**。

### 诊断过程

1. 初步怀疑 max_tokens=256 太小 → 改为 1024
2. 重启后仍然报错
3. 添加诊断日志，发现：content_length=0 reasoning_present=True
4. 确认：API 有响应，但 content 为空而 reasoning_content 有内容

### 修复方案

文件：app/translation/client.py 第 205-219 行

修改 _extract_content 方法，当 content 为空时尝试从 reasoning_content 提取。

### 验证方法

1. 重启应用
2. 翻译任意文本
3. 应该不再出现 "API returned an empty translation"

### 说明

DeepSeek 的行为：
- thinking 模式开启时，模型的推理过程放在 reasoning_content
- 有时翻译结果也在 reasoning_content 而非 content
- 我们的代码现在会自动 fallback 到 reasoning_content

## 问题诊断：DeepSeek API 返回空翻译

### 现象
- API 频繁返回 "API returned an empty translation"
- 有时输出中文推理过程，不是翻译结果
- 选择框内容变化后翻译停止

### 根本原因
1. **DeepSeek Thinking 行为不稳定**：content 经常为空，只有 reasoning_content
2. **Agent Messages 累积**：对话越长，模型越困惑
3. **Prompt 约束冲突**：平假名约束 vs 实际输入（英文+数字+符号）
4. **错误的 Fallback**：当 content 为空时，读取 reasoning_content（推理过程）

### 提出的解决方案
1. **方案 1**：移除 reasoning_content fallback（立即）
2. **方案 2**：实现 Agent messages compact，保留最近 5 轮（根本）
3. **方案 3**：简化或修改 prompt 约束（治标）
4. **方案 4**：关闭 thinking 模式（最后手段）

### 需要 Oracle 评审的问题
1. DeepSeek thinking 是否适合 Agent 持久化会话？
2. Prompt 约束的最佳表达方式？
3. Messages compact 的最佳策略（保留多少轮？术语提取？）

### 状态
- 已完成详细分析，写入 `docs/communication/02-专家反馈.md`
- 等待与另一位 AI 讨论后决定实施方案
