## 问题诊断：DeepSeek API 返回空翻译

### 现象
- API 频繁返回 "API returned an empty translation"
- 有时输出中文推理过程，不是翻译结果
- 选择框内容变化后翻译停止

### 根本原因
1. **DeepSeek Thinking 行为不稳定**：content 经常为空，只有 reasoning_content
2. **Agent Messages 累积**：对话越长，模型越困惑
3. **Prompt 约束冲突**：平假名约束 vs 实际输入（英文+数字+符号）
4. **错误的 Fallback**：当 content 为空时，读取 reasoning_content（推理过程）

### 提出的解决方案
1. **方案 1**：移除 reasoning_content fallback（立即）
2. **方案 2**：实现 Agent messages compact，保留最近 5 轮（根本）
3. **方案 3**：简化或修改 prompt 约束（治标）
4. **方案 4**：关闭 thinking 模式（最后手段）

### 需要 Oracle 评审的问题
1. DeepSeek thinking 是否适合 Agent 持久化会话？
2. Prompt 约束的最佳表达方式？
3. Messages compact 的最佳策略（保留多少轮？术语提取？）

## 深度思考：改写方案的理解

### 认知转变

**之前的误解**：
- 以为改写是"修正"用户错误
- 担心改变用户意图
- 认为需要规则引擎检测绝对化模式

**正确理解**：
- 改写是"翻译"用户意图给 AI
- 用户有最终确认权
- 利用 LLM 能力，不需要规则引擎
- 目的是让翻译 AI 更懂用户

### 方案优势

1. 用户友好：不需要学习如何写 prompt
2. 保持原意：改写是更清晰表达
3. 灵活智能：LLM 理解各种表述
4. 用户掌控：最终确认权在用户

### 关键问题：POC 数据太少

当前 POC 混合输入只测了 1 条，不足以验证方案有效性。

## 重要纠正：速度慢的根因是"约束没分层"，不是"缺术语索引"

### 我的错误判断

对照原规划后，我判断：
- 速度慢 = 缺术语索引（glossary.py）
- 建议补全 Agent 核心组件

### 另一个 AI 的纠正 ✅

**术语索引在字幕场景没用**：
- 即时字幕每句都是新的
- "Team车位70-80r" 和 "拼一个GPT账号" 之间没有可复用术语
- 命中率趋近于零
- 加 glossary 不会让 15s → 2s

**真正的根因：约束没分层**

| 约束类型 | 例子 | 处理方式 | 延迟 |
|---------|------|---------|:---:|
| 字符级 | 平假名、全角、禁止汉字 | 本地后处理 | 0ms |
| 语义级 | 语气、风格、术语选择 | Agent thinking | 5-15s |

### 这解释了之前的 content 为空 Bug

```
约束："只能平假名"（字符级）
输入："Team车位70-80r"
模型：在"怎么把 Team 翻译成平假名"上烧 900 tokens reasoning
结果：content 为空
```

**字符级约束不该丢给模型思考！**
应该本地处理：OCR 输出 → 平假名映射 → 全角转换 → 0 延迟

### 关键认识：max_tokens=4096 是治标

- 给了足够空间让模型烧 reasoning
- 但模型还在做不该做的事（字符转换）
- 真正治本：字符约束本地处理，模型不纠结

### 正确的执行方向

新架构：
```
OCR → 后处理(0ms) → Agent(5-15s) → 输出
       ↑                ↑
    字符级约束        语义级约束
```

具体实施：
1. 新建 app/agent/postprocess.py（字符级约束本地处理）
2. Agent 消化时区分：字符约束→后处理，语义约束→thinking
3. 翻译管线：OCR → 后处理 → Agent → 输出

### 我的反思

**我又犯了 3 个错误**：
1. 没深挖自己的疑问（问了术语命中率，但没继续想）
2. 被原规划带偏（规划写了术语索引就以为缺它=慢）
3. 没区分约束类型（把所有约束都当成需要 AI 思考的）

**判断演进**：
- 第1次：约束矛盾（触因）
- 第2次：max_tokens（解决空content，但治标）
- 第3次：缺术语索引（方向错）
- AI纠正：约束没分层（根本）✅

### 收获

- 字符级 vs 语义级约束的区分
- 本地后处理的价值（0 延迟）
- 不要被现有规划限制独立思考
