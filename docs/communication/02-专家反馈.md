## 🐛 当前待解决问题：DeepSeek API 返回空翻译

### 问题现象

用户报告翻译功能不稳定：
1. API 频繁返回空翻译错误："API returned an empty translation"
2. 有时输出的是中文推理过程，不是翻译结果
3. 选择框内容变化后，翻译停止工作

### 实际日志证据

**Pipeline 日志**：
```
19:14:45 | INFO  | [G1] 中文→日本語 | API: 'ほうはんじゅうりょくのげみにぷろにじゅうろく' (21572ms)  # 正常翻译
19:16:12 | INFO  | [G1] 中文→日本語 | API: '我们需要将用户输入的中文内容翻译成日语...' (15317ms)  # 输出推理过程
19:17:34 | INFO  | [G1] 中文→日本語 | API: '我们需要理解用户的输入内容。用户给了一段文字...' (13164ms)  # 输出推理过程
```

**Debug 日志（关键证据）**：
```
19:14:45 | DEBUG | API response: content='ほうはんじゅうりょく...' reasoning_present=True  # 正常
19:15:19 | DEBUG | API response: content_preview=(empty) reasoning_present=True  # content 为空
19:16:12 | DEBUG | API response: content_preview=(empty) reasoning_present=True  # 持续为空
```

**Reasoning 内容**：
```
我们需要将用户输入的中文内容翻译成日语，并且输出必须完全由平假名构成，不能有汉字、片假名或其他字符。用户输入是："拼一-个Team车位,主要用Web,稳定长期优先,接受价位70-80r..." 但输入包含英文字母、数字、符号，约束说只能平假名，怎么处理？
```

---

## 🔍 根本原因分析

### 1. DeepSeek Thinking 模式行为不稳定

**预期**：
- `reasoning_content` = 推理过程
- `content` = 翻译结果

**实际**：
- 首次翻译：`content` 有内容 ✅
- 后续翻译：`content` 经常为空 ❌

### 2. Agent Messages 累积导致混乱

```
第 1 次：messages = [system, 规则, user1, assistant1] → 正常 ✅
第 2 次：messages = [system, 规则, user1...2, assistant1...2] → 困惑 ⚠️
第 5 次：messages = [system, 规则, user1...5, assistant1...5] → 混乱，content="" ❌
```

### 3. Prompt 约束与实际输入冲突

**约束**：`如果中文翻译为日语时，翻译的日语句子只能由平假名构成。`

**实际输入**：`"拼一个Team车位,主要用Web,稳定长期优先,接受价位70-80r"`

**冲突**：包含英文（Team、Web）、数字（70-80）、符号，DeepSeek 不知道如何处理

### 4. 错误的 Fallback 逻辑

当前代码（`app/translation/client.py`）：
```python
if not content.strip() and "reasoning_content" in msg:
    content = msg.get("reasoning_content") or ""  # 拿到的是推理过程！
```

---

## 🎯 提出的解决方案

### 方案 1：移除 reasoning_content fallback ✅

**修改**：不要 fallback 到 reasoning_content
```python
@staticmethod
def _extract_content(response_json: dict) -> str:
    msg = response_json["choices"][0]["message"]
    return msg.get("content") or ""  # 直接返回，不要 fallback
```

**优点**：不会再输出推理过程  
**风险**：content 为空时会报错（但这比输出推理好）

---

### 方案 2：Agent Messages Compact ✅✅✅

**修改**：限制 messages 长度
```python
# app/agent/agent.py
MAX_HISTORY_PAIRS = 5  # 保留最近 5 轮

def translate(self, text: str) -> str:
    self.messages.append({"role": "user", "content": text})
    
    # Compact: 保留 system + 规则 + 最近 5 轮
    if len(self.messages) > 3 + (MAX_HISTORY_PAIRS * 2):
        keep = MAX_HISTORY_PAIRS * 2
        self.messages = self.messages[:3] + self.messages[-keep:]
    
    resp = self._client.chat(self.messages, thinking=True)
    self.messages.append({"role": "assistant", "content": resp})
    return resp
```

**优点**：避免上下文过长  
**风险**：丢失早期翻译的上下文

---

### 方案 3：简化/修改 Prompt 约束 ⚠️

**选项 A**：删除平假名约束（GUI 操作）

**选项 B**：修改为条件性
```
如果原文只包含中文和日文汉字，则日语输出只使用平假名。
如果原文包含英文、数字或符号，则合理保留或转换。
```

---

### 方案 4：关闭 Thinking 模式 ⚠️ (最后手段)

```python
# app/agent/agent.py
resp = self._client.chat(self.messages, thinking=False)
```

**优点**：避免 thinking 不稳定  
**代价**：失去推理优势、首次消化变慢

## 🔬 需要评审的问题

### 问题 1：DeepSeek Thinking 适合持久化会话吗？

**观察**：对话越长，content 越容易为空

**疑问**：
- Thinking 是否更适合单次请求？

**疑问**：
- 约束应该是"建议"还是"强制"？
