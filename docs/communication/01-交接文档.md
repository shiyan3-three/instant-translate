## 项目概述

**Instant Translate** - Windows 桌面即时翻译工具

用户框选屏幕区域（如游戏字幕），软件持续 OCR 识别文字变化，调用 AI 翻译并在悬浮窗显示。支持最多 3 组独立翻译流程。

**项目地址**：https://github.com/shiyan3-three/instant-translate

---

## 技术栈

- **语言**：Python 3.9
- **GUI**：PySide6 (Qt)
- **OCR**：PaddleOCR 2.7.3 + Tesseract (fallback)
- **AI**：OpenAI 兼容 API（主要使用 DeepSeek）
- **打包**：PyInstaller → ~720MB exe

---

## 核心架构

```
用户框选区域
    ↓
每 500ms 截图
    ↓
BLAKE2b 哈希检测变化
    ↓
OCR 识别文字 (PaddleOCR)
    ↓
TranslationAgent 翻译 (thinking 模式)
    ↓
悬浮窗显示结果
```

### 关键设计

1. **Agent 化翻译**（2026-06-11 完成）
   - 规则消化一次（5-10s，thinking 模式）
   - 后续翻译复用会话（1.4-1.6s）
   - thinking 推理自然衰减（128 → 24-59 tokens）

2. **按组独立 Agent**（2026-06-12 完成）
   - 每组（group）独立 Agent 实例
   - 不同语言对不互相污染
   - 删除组时清理内存

3. **Prompt 三层架构**
   - 固定模板层（系统维护）
   - 约束层（用户编辑）
   - 知识引用层（术语表、风格指南）

## 技术债务

### 高优先级

1. **OCR 实例复用**
   - 问题：每次 warmup 都重新初始化（耗时 2-5s）
   - 位置：`app/ocr/engine.py` 的 `_warmup` 方法
   - 诊断：已添加日志，待查看 `instance_id`

2. **Agent 上下文 compact**
   - 问题：messages 数组无限增长
   - 方案：保留术语 KV + 最近 N 轮 + 旧内容摘要
   - 优先级：中（当前使用场景下尚可）

### 中优先级

3. **GUI 响应性优化**
   - 编辑模式下的闪烁问题（已通过状态比对缓解）
   - 长文本加载时的卡顿

4. **错误恢复**
   - API 超时后的自动重试
   - OCR 失败时的 fallback 策略

## 常见陷阱

1. **不要新建临时文档** - 追加到现有文档
2. **Agent 实例复用** - 确保 `TranslationService._agents` 是字典，不是每次新建

4. **测试前加 mock** - 避免调用真实 API
5. **语法检查** - 修改后运行 `python -m py_compile <file>`
