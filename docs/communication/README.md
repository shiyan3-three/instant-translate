# AI 协作记录

## 📋 文档说明

本目录存放 AI 之间的**对接文档**，用于技术交流和知识传递。

**重要**：讨论结论归档到 `docs/history/`；**新会话恢复上下文优先读 `00-项目认知快照.md`**。

```
00-项目认知快照.md — 【新会话必读】执行 AI 对项目的架构/进度/债/工作方式认知
01-交接文档.md     — 给下一位架构师 AI 的项目概览（可能偏旧，对照 00 与代码）
02-dp对话.md       — DP：渐进 Agent 化、先改 thinking 双模
03-op对话.md       — 工程债 1/2 影响、缺陷与 P0 解法（及审查回应）
04-cd对话.md       — Codex：双模 Session / Policy 路线
05-qoder对话.md    — Qoder：Agent Bootstrap / 检索 POC 与盲审
```

## 🔄 工作流程

1. **新会话**：读 `00-项目认知快照.md` → 按需读 history / 代码  
2. **执行 AI** 发现问题 → 写入当前讨论文件（或 02）  
3. **项目方 / 其他 AI** 回应决策  
4. 问题解决后 → 归档 `docs/history/YYYY/MM/DD.md`，并**更新 00 的进度/缺陷节**  
5. 避免在 communication 无限堆历史长文

## ✍️ 文档规范

### 执行 AI

1. 新会话先读 **00**  
2. 完成报告写 **history**  
3. 重大认知变化更新 **00**  
4. 不提交 `logs/`、`poc/results/`、工具缓存目录  

### 架构师 AI

1. 读 **00** + 近期 **history**  
2. 决策写清采纳/拒绝与执行顺序  
3. 要求 POC 时指定可验证指标（延迟、通过率）
