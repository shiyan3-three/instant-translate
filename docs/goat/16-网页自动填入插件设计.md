# 16 · 网页自动填入插件设计

> **状态**：草案（已讨论冻结产品语义，实现未开工）  
> **日期**：2026-07-16  
> **目的**：把「桌面 OCR / AI 译文 → 网页输入框自动写入」的产品规则、接口与 JS 侧实现要点写清，方便后续做浏览器插件时不重新扯皮。  
> **相关**：`app/overlay/*`（OCR/译文框体）、`app/overlay/selection_manager.py`（稳定 OCR 与译出）、浏览器扩展（未建仓）。

---

## 1. 一句话

用户在**网页**上先点好输入框，再在**本软件**（OCR 框 / 译文框工具栏）打开互斥开关之一；等软件侧 **OCR 框与译文框都已稳定出字** 后，把**当前打开的那一路**文本自动写入该网页输入框。只写入，不提交表单。

---

## 2. 产品语义（已拍板）

### 2.1 角色

| 角色 | 说明 |
|------|------|
| 内容来源 | **本翻译软件**流水线结果：① 区域 OCR 清洗后展示在 OCR 框的正文；② AI 译完后展示在译文框的正文。**不是**网页里另造的假文本。 |
| 写入目标 | 仅**网页**中用户事先选中/聚焦过的 `input` / `textarea` / `[contenteditable]` |
| 开关 UI | 软件侧 OCR 框、译文框工具栏上各一个开关按钮 |
| 稳定门槛 | **两路框体都已稳定显示内容**之后才允许写入（与现有 OCR 稳定窗 + 译出落窗语义对齐） |
| 写哪一路 | 由**当前打开的开关**决定：开 OCR → 写 OCR 文本；开译文 → 写译文文本 |

### 2.2 用户步骤

```text
1. 在浏览器页面中点击目标输入框（插件记住 target）
2. 在软件 OCR 框或译文框工具栏打开其中一个自动填入开关（可自关；开 A 会关 B）
3. 软件继续跑 OCR / 翻译；当 OCR 框与译文框均已稳定出字
4. 插件（或桥）把「当前打开来源」的文本写入步骤 1 的输入框
5. 不自动点提交 / 登录 / 发送
```

### 2.3 开关状态机

- 形态：开关（亮 = 开，再点自己 = 关）。
- **互斥开启**：打开 A 时若 B 已开 → 先关 B 再开 A。
- **可单独关闭**：不必通过点击另一个才能关掉当前；再点自己即可关。
- 两路都关：不自动写入。
- 仅一路开：仍须等**两路框体都稳定**才写（门槛是双稳定；内容取开启的那一路）。

### 2.4 「稳定」含义（产品）

| 框体 | 稳定含义（与实现挂钩时） |
|------|--------------------------|
| OCR 框 | 该组 OCR 文本已通过现有稳定策略并**已展示在 OCR 悬浮窗**（不是半截 candidate） |
| 译文框 | 该组 AI 翻译已成功返回且**已展示在译文悬浮窗**（非「翻译失败：…」类错误文案，除非产品另定） |

「双稳定」= 同一 `group_id` 上 OCR 展示文本与译文展示文本都处于稳定可用态。  
若开了开关但长期达不到双稳定：**不写**；UI 可提示「等待 OCR/译文稳定」（实现阶段再定文案）。

### 2.5 非目标（边界）

- 不自动提交表单、不模拟回车发送。
- 不跨桌面抓第三方窗口文字（内容只来自本软件）。
- 不要求纯网页 JS 在无扩展/无桥接时直接读桌面控件（做不到）。
- 不默认写入 `type=password`（建议默认跳过；可配置后续再说）。
- 不处理跨域 iframe 内部输入（除非扩展有额外权限且明确支持）。

## 4. 桌面侧状态与接口

### 4.1 概念类型（逻辑，非最终 Python 名）

```text
FillSource = "ocr" | "translation"

FillInGroupState:
  group_id: int
  ocr_text: str
  translation_text: str
  ocr_stable: bool          # 已稳定展示在 OCR 框
  translation_stable: bool  # 已稳定展示在译文框
  active_source: FillSource | null   # 互斥开关；null = 两路都关

FillPayload:                 # 推到浏览器
  v: 1
  type: "fill"
  group_id: int
  source: FillSource
  text: str
  ts: number                 # unix ms
  request_id: string         # 幂等 / 去重
```

### 4.2 开关 API（桌面逻辑）

```text
toggle_fill_source(group_id, source: FillSource) -> active_source
  # 若当前已是 source 且开着 → 关闭 → null
  # 若当前是另一 source → 关掉另一 → 打开 source
  # 若当前 null → 打开 source

clear_fill_source(group_id) -> null

get_fill_state(group_id) -> FillInGroupState
```

工具栏：

- OCR 框角栏/工具：`fill_ocr` 开关，绑定 `source="ocr"`
- 译文框角栏/工具：`fill_translation` 开关，绑定 `source="translation"`
- 高亮 = `active_source == 该 source`

### 4.3 何时推送 FillPayload

伪代码：

```text
on_ocr_stable(group_id, text):
  state.ocr_text = text
  state.ocr_stable = true
  try_emit_fill(group_id)

on_translation_stable(group_id, text):
  state.translation_text = text
  state.translation_stable = true
  try_emit_fill(group_id)

on_toggle_fill(group_id, source):
  update active_source
  try_emit_fill(group_id)

try_emit_fill(group_id):
  s = state[group_id]
  if s.active_source is null: return
  if not (s.ocr_stable and s.translation_stable): return
  text = s.ocr_text if s.active_source == "ocr" else s.translation_text
  if not text.strip(): return
  # 可选：与上次成功 payload 相同则跳过，避免 OCR 微抖重复刷网页
  bridge.publish(FillPayload(...))
```

**与现网挂钩（实现时）**

- OCR 稳定：对齐 `selection_manager` 中 OCR 稳定窗结束后写入 `latest_ocr_text` 并刷新 OCR 窗的时机。
- 译文稳定：对齐翻译成功 `_translation_ready` / 译文窗 `apply_model` 展示成功文本的时机。
- 错误译文（如 `翻译失败：…`）建议 `translation_stable=false` 或不推送。

### 4.4 本地桥（桌面进程内）

推荐 **WebSocket** `ws://127.0.0.1:<port>/v1/fill`（HTTP 长轮询作备选）。

**安全**

- 只绑 `127.0.0.1`
- 启动时生成 `session_token`（写入扩展可配置的本地文件或 Native Messaging；MVP 可用用户复制一次 token）
- 所有客户端消息带 `Authorization: Bearer <token>` 或首帧 `auth` 消息

**服务端 → 扩展（下行）**

```json
{
  "v": 1,
  "type": "fill",
  "group_id": 1,
  "source": "translation",
  "text": "大学入学共通テストがまもなく始まる",
  "ts": 1720000000123,
  "request_id": "g1-1720000000123-a1b2"
}
```

**扩展 → 服务端（上行，可选）**

```json
{ "v": 1, "type": "ack", "request_id": "g1-1720000000123-a1b2", "ok": true }
{ "v": 1, "type": "ack", "request_id": "...", "ok": false, "error": "no_target" }
{ "v": 1, "type": "hello", "token": "...", "extension_version": "0.1.0" }
{ "v": 1, "type": "target_changed", "has_target": true, "tag": "textarea" }
```

**服务端 → 扩展（状态）**

```json
{
  "v": 1,
  "type": "state",
  "group_id": 1,
  "active_source": "ocr",
  "ocr_stable": true,
  "translation_stable": false
}
```

端口：可配置，默认例如 `8765`；冲突则递增并写入 `%APPDATA%/instant-translate/fill-bridge.json`。

## 5. 浏览器扩展（JS）设计

### 5.1 模块

| 脚本 | 职责 |
|------|------|
| `background.js`（service worker） | 连 `ws://127.0.0.1:…`，鉴权，把 `fill` 转给当前标签 content script |
| `content.js` | 记焦点目标；执行写入；回 ack |
| `popup.html`（可选） | 连接状态、清除目标、测试写入 |

### 5.2 Content Script：记住输入源

```javascript
// content.js — 焦点记忆（MVP 草图）

const WRITEABLE_SELECTOR = [
  "input:not([type=hidden]):not([type=button]):not([type=submit]):not([type=checkbox]):not([type=radio])",
  "textarea",
  "[contenteditable='']:not([contenteditable=false])",
  "[contenteditable=true]",
].join(",");

/** @type {HTMLElement | null} */
let lastTarget = null;

function isWriteable(el) {
  if (!el || !(el instanceof HTMLElement)) return false;
  if (el.closest("[data-instant-translate-ignore]")) return false;
  if (el instanceof HTMLInputElement) {
    const t = (el.type || "text").toLowerCase();
    if (t === "password" || t === "file" || t === "hidden") return false;
    if (el.disabled || el.readOnly) return false;
    return true;
  }
  if (el instanceof HTMLTextAreaElement) {
    return !el.disabled && !el.readOnly;
  }
  if (el.isContentEditable) return true;
  return false;
}

function rememberTarget(el) {
  if (!isWriteable(el)) return;
  lastTarget = el;
  // 可选：通知 background 有目标
  chrome.runtime.sendMessage({ type: "target_changed", has_target: true, tag: el.tagName });
}

document.addEventListener(
  "focusin",
  (e) => {
    const t = e.target;
    if (t instanceof HTMLElement) rememberTarget(t);
  },
  true
);

// 点击也可能选中（部分站点 focus 行为怪）
document.addEventListener(
  "click",
  (e) => {
    const t = e.target;
    if (t instanceof HTMLElement) {
      const host = t.closest(WRITEABLE_SELECTOR);
      if (host instanceof HTMLElement) rememberTarget(host);
    }
  },
  true
);
```

### 5.3 写入目标元素（兼容受控组件）

```javascript
// content.js — 写入

function setNativeValue(el, value) {
  if (el instanceof HTMLInputElement || el instanceof HTMLTextAreaElement) {
    const proto =
      el instanceof HTMLTextAreaElement
        ? HTMLTextAreaElement.prototype
        : HTMLInputElement.prototype;
    const desc = Object.getOwnPropertyDescriptor(proto, "value");
    if (desc && desc.set) desc.set.call(el, value);
    else el.value = value;
    el.dispatchEvent(new Event("input", { bubbles: true }));
    el.dispatchEvent(new Event("change", { bubbles: true }));
    return;
  }
  if (el.isContentEditable) {
    el.focus();
    // 简单整段替换；站点若用复杂编辑器需后续专项适配
    el.textContent = value;
    el.dispatchEvent(new InputEvent("input", { bubbles: true, data: value }));
  }
}

function fillLastTarget(text) {
  const el = lastTarget;
  if (!el || !document.contains(el)) {
    return { ok: false, error: "no_target" };
  }
  if (!isWriteable(el)) {
    return { ok: false, error: "target_not_writeable" };
  }
  try {
    el.focus();
    setNativeValue(el, text);
    return { ok: true };
  } catch (err) {
    return { ok: false, error: String(err && err.message ? err.message : err) };
  }
}
```

### 5.4 Background：桥接桌面

```javascript
// background.js — WebSocket 草图

let ws = null;
let token = ""; // 从 storage 读取
const PORT = 8765; // 或从 storage / fill-bridge.json 同步

function connect() {
  if (ws && (ws.readyState === WebSocket.OPEN || ws.readyState === WebSocket.CONNECTING)) {
    return;
  }
  ws = new WebSocket(`ws://127.0.0.1:${PORT}/v1/fill`);
  ws.onopen = () => {
    ws.send(JSON.stringify({ v: 1, type: "hello", token, extension_version: "0.1.0" }));
  };
  ws.onmessage = async (ev) => {
    let msg;
    try {
      msg = JSON.parse(ev.data);
    } catch {
      return;
    }
    if (msg.type !== "fill") return;
    const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });
    if (!tab || tab.id == null) {
      ws.send(JSON.stringify({ v: 1, type: "ack", request_id: msg.request_id, ok: false, error: "no_tab" }));
      return;
    }
    const res = await chrome.tabs.sendMessage(tab.id, {
      type: "fill",
      text: msg.text,
      request_id: msg.request_id,
      source: msg.source,
      group_id: msg.group_id,
    });
    ws.send(
      JSON.stringify({
        v: 1,
        type: "ack",
        request_id: msg.request_id,
        ok: !!(res && res.ok),
        error: res && res.error,
      })
    );
  };
  ws.onclose = () => {
    setTimeout(connect, 1500);
  };
}

chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => {
  // content → background 的 target_changed 等
  if (msg && msg.type === "target_changed" && ws && ws.readyState === WebSocket.OPEN) {
    ws.send(JSON.stringify({ v: 1, type: "target_changed", has_target: msg.has_target, tag: msg.tag }));
  }
  return false;
});

// content 收 fill
// 在 content.js:
chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => {
  if (msg && msg.type === "fill") {
    sendResponse(fillLastTarget(String(msg.text ?? "")));
    return true;
  }
});
```

### 5.5 去重与幂等

- 同一 `request_id` content 只写一次。
- 桌面侧：同一 `group_id+source+text` 在开关持续开启时，**文本未变不重复推**；文本变更且仍双稳定 → 可再推（用户改 OCR 区域后更新网页）。

## 7. 时序图（逻辑）

```text
用户 focus 网页 textarea
    → content 记 lastTarget

用户打开译文框「自动填入」开关
    → active_source=translation（若 OCR 开着则关掉）

OCR 稳定落窗
    → ocr_stable=true
    → try_emit：translation 尚未 stable → 不发

译文 API 成功落窗
    → translation_stable=true
    → try_emit：双稳定且 active=translation → bridge fill

background 收到 fill
    → 当前标签 content fillLastTarget(text)

content 写入 + ack
```

## 9. 测试要点

- 互斥：开译文后 OCR 必关；再点译文可单独关。
- 双稳定门槛：仅 OCR 稳定不推；仅译文稳定不推。
- 无 lastTarget：ack `no_target`，桌面可提示。
- 同一 request_id 不写两次。
- BOM/编码：推送 JSON 一律 UTF-8。
- 关闭开关后不再推送。
- 组删除 / 编辑模式重置时 `active_source=null`。

## 10. 开放项（实现前可再定）

| 项 | 默认建议 |
|----|----------|
| 多 group 同时开开关 | MVP 仅允许一组 active；其它组开开关时提示 |
| 错误译文是否算 stable | 否 |

## 11. 决策摘要（可同步进 13-决策记录）

1. 内容只来自**本软件** OCR 框与 AI 译文框，不是网页自造文本。  
2. 用户必须**先**在网页选输入框，再开软件侧开关。  
3. 开关为可自关的互斥开关，不是强制二选一单选组。  
4. **OCR 与译文都稳定展示后**才写入；写哪一路看当前开关。  
5. 只写入，不提交表单。  
6. 实现形态：桌面 + 本机桥 + 浏览器扩展（不能单靠无权限网页脚本读桌面）。
