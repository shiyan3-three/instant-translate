# 后期技术债清单

> 记录日期：2026-07-15  
> 范围：仅记录不适合与当前小型修复混在一起、需要分阶段实施和回归验证的工程工作。

## 明确不属于技术债

- DPAPI 密文只能由当前 Windows 用户解密：这是预期的安全隔离，不应为了配置可搬运而削弱。
- Python 3.9 及更早版本不支持：项目公开边界为 Python `>=3.10,<3.13`，`zip(..., strict=True)` 无需兼容性降级。
- 真实多显示器硬件测试：当前产品使用范围不要求将其列为待办。

## 第一阶段：模块职责拆分

### 1. 拆分 GUI 巨型模块

- 当前 `app/gui/main_window.py` 同时包含模板、模型、反馈、设置页面和主窗口编排。
- 按页面拆为独立模块，主窗口只负责导航、依赖注入和跨页协调。
- 先补行为特征测试，再逐页迁移；禁止同时调整交互和视觉设计。

### 2. 拆分 FeedbackStore

- 当前 `app/feedback/store.py` 混合持久化、迁移、事务恢复、状态流转、规则匹配和查询。
- 建议拆成 repository、migration、transaction、rule/correction service 等边界。
- 每次只迁移一种职责，保留现有文件格式与兼容迁移能力。

### 3. 拆分 TranslationService 与 Agent

- `TranslationService` 当前同时负责任务编排、Prompt/策略解析、记忆检索、会话持久化和并发控制。
- `TranslationAgent` 同时承担 API 调用、重试、输出恢复、校验和 best-effort 策略。
- 后期应将策略和副作用分开，使重试、校验、记忆注入能够独立测试。

## 第二阶段：运行时和网络层

### 4. 实现进行中 HTTP 请求的真实取消

- 当前关闭或请求过期后会使结果失效并阻止 UI 更新，但同步 HTTP 调用仍可能运行到超时。
- 需要评估长生命周期 `httpx.Client`/`AsyncClient`、取消令牌和 Qt 事件循环之间的集成。
- 改造必须覆盖窗口关闭、组删除、语言切换、Pro retry 和应用退出。

### 5. 统一网络连接生命周期

- 复用连接池，减少重复 TLS 建连。
- 明确 client 的 owner、关闭顺序、超时分类和重试边界。
- 与“真实取消”一起设计，避免先做一次性局部封装后再次推倒。

### 6. 建立系统化异常分类

- 后台线程和 Qt 边界允许最终兜底 `except Exception`，但业务模块应区分配置、存储、网络、校验和生命周期错误。
- 逐模块治理，不做一次性全局机械替换。
- 目标是错误可观察、用户提示明确，同时不让后台异常穿透导致 Qt 崩溃。

## 第三阶段：发布体积和依赖演进

### 7. PyInstaller 整体瘦身

- 当前 onedir 约 786 MB，完整收集了 PaddleOCR/Paddle 的较大依赖树。
- 通过实际导入图和运行 profiling，逐步排除训练、表格、版面分析、绘图和文档处理模块。
- 每次排除后必须执行干净构建以及 `instant-translate.exe --smoke-ocr`，不能只看构建是否成功。
- 体积优化不得再次遗漏 `ppocr/tools`、Cython Utility、包元数据或 Paddle DLL。

### 8. OCR 依赖升级路线

- 当前稳定基线是 Python 3.12、PaddlePaddle 2.6.2、PaddleOCR 2.7.3、NumPy 1.x。
- Paddle/Protobuf 已产生多项弃用警告，未来升级应单独建立兼容性分支和真实 OCR 基准。
- 在新组合完成准确率、冷启动、长时间运行和冻结版测试前，不更换当前发布基线。

## 第四阶段：产品复杂度评估

### 9. 反馈、记忆和 RAG 系统瘦身

- 评估 generation、digest、权威反馈检索、规则巩固和远程向量后端是否都产生实际用户价值。
- 先增加使用数据和失败样本统计，再决定保留、合并或删除模块。
- 不以“架构看起来完整”为理由继续增加层级。

## 后期重构统一验收规则

- 一次只处理一个职责边界，不与功能开发混合。
- 修改前增加行为特征测试，修改后保持文件格式和用户配置兼容。
- 使用 Python 3.12 执行全量测试、`pip check`、`compileall` 和 `git diff --check`。
- 涉及 OCR、依赖或 spec 时，必须重新执行干净 PyInstaller 构建与冻结版 OCR 烟测。
- 不重置、不覆盖、不删除用户已有未提交修改。
