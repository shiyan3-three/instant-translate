# Prompt 系统设计

## 1. 设计目标

本项目的 Prompt 系统不只是一个文本输入框，而是一个可控的 Prompt 编译机制。

它要解决的问题包括：

- 保证系统在用户不自定义时也有完整 Prompt
- 支持用户逐步增加翻译约束，而不是直接破坏基础模板
- 支持通过知识文档补充术语、风格和固定表达
- 让最终实际生效的 Prompt 可预览、可确认、可保存

## 2. 设计原则

- 固定模板层必须始终完整存在
- 用户输入必须和系统模板解耦
- 知识引用层必须先提炼再参与编译
- 运行时翻译阶段不得重新编译 Prompt
- 新 Prompt 必须经过用户确认后才能启用

## 3. 三层架构

## 3.1 固定模板层

固定模板层是系统级基础 Prompt。

它负责定义：

- 角色定位
- 翻译任务边界
- 输出格式
- 禁止解释、禁止扩写、禁止分析
- 不完整文本时的保守处理方式

这个层级必须最高优先级，且即使其他层为空，也要能独立支持整个翻译链路。

## 3.2 约束层

约束层由用户手动输入，表达个性化翻译需求。

典型内容包括：

- 翻译偏直译还是偏自然表达
- 是否保留专有名词原文
- 是否偏向学习场景
- 对句式和语气的偏好

## 3.3 知识引用层

知识引用层由用户提供本地文档路径，默认以 Markdown 文档为主。

这些文档可包含：

- 术语表
- 固定译法
- 句式风格
- 特定领域词汇
- 专有名词对照

## 4. 优先级模型

三层优先级固定如下：

`固定模板层 > 约束层 > 知识引用层`

解释如下：

- 固定模板层负责保证 Prompt 完整性和系统边界
- 约束层负责用户对翻译方式的明确要求
- 知识引用层负责补充领域知识，不应主导系统边界

## 5. 编译流程

Prompt 编译流程如下：

1. 读取固定模板层
2. 读取约束层输入
3. 读取知识引用层文档
4. 对知识文档做提炼
5. 生成 Prompt 预览
6. 用户确认
7. 保存并启用 `compiled prompt`

## 6. 知识引用层提炼

知识引用层不能整篇文档原样注入运行时 Prompt。

推荐提炼结果为以下三类：

- 术语表
- 风格规则
- 固定表达

必要时可借助 AI 辅助整理，但产物必须结构化、可读、可预览。

## 7. 是否使用 AI 参与编译

本项目允许使用 AI 对约束层和知识引用层做理解和优化。

推荐方式：

- 约束层：由 AI 做归纳和表达规整
- 知识引用层：由 AI 做摘要、术语提炼和风格提炼
- 固定模板层：不经 AI 改写，保持系统控制权

但必须满足：

- 这种编译仅发生在配置阶段
- 不发生在运行时翻译阶段

## 8. 用户交互流程

推荐 GUI 流程如下：

1. 用户编辑约束层文本
2. 用户添加、删除知识引用文档
3. 用户点击“生成预览”
4. 系统执行 Prompt 编译
5. GUI 显示 `compiled prompt` 预览
6. 用户点击“确认保存并启用”
7. 新 Prompt 成为当前运行版本

这意味着：

- 用户可以看到真正生效的 Prompt
- 用户不会在不知情的情况下直接启用新规则

## 9. 文件保存建议

推荐至少保存以下内容：

- `constraints.md`：约束层原始输入
- `knowledge-references.json`：知识引用文档列表
- `compiled-prompt.md`：当前启用的最终 Prompt

说明：

- 固定模板层可内置在程序资源中，不一定暴露为用户直接编辑文件
- `compiled-prompt.md` 应作为运行时默认读取版本

## 10. 运行时策略

运行时翻译阶段应遵守以下规则：

- 只读取当前启用的 `compiled prompt`
- 不重新解析原始三层输入
- 不重新触发 Prompt 编译
- 配置变更后，只有在用户确认并保存后才切换到新版本

## 11. 异常与边界

### 11.1 用户不填写约束层和知识引用层

系统必须仍可稳定运行，直接使用固定模板层生成有效 Prompt。

### 11.2 知识文档内容过长

应限制知识提炼阶段的输入规模，必要时提醒用户裁剪内容或拆分文档。

### 11.3 编译结果质量差

若 AI 生成的 Prompt 预览不理想，用户可以不确认启用，继续修改第二层和第三层后重试。

## 12. 与项目整体的关系

Prompt 系统是本项目 AI 依赖可控化的关键一环。

它的价值不只是“让用户能写 Prompt”，而是：

- 保证基础能力完整
- 保证用户增强能力可控
- 保证运行时延迟不被 Prompt 编译拖垮
- 保证调试、维护和长期使用体验

## 13. 结论

本项目的 Prompt 系统应被视为一个独立模块，而不是一个表单输入框。

它的最终目标不是“更灵活”，而是：

- 更完整
- 更稳定
- 更可预期
- 更适合长期个人使用与开源维护
