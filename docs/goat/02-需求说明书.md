# 即时字幕翻译悬浮窗软件需求说明书

## 1. 文档信息

- 项目名称：即时字幕翻译悬浮窗软件
- 项目形态：Windows 桌面软件
- 文档类型：需求说明书
- 文档日期：2026-05-22
- 文档状态：需求已确认，可进入实现设计阶段

## 2. 项目概述

本项目面向 Windows 桌面场景，提供“框选固定区域 + 持续 OCR 识别 + AI 翻译 + 悬浮窗展示”的即时翻译能力。用户可以通过全局快捷键快速创建最多 3 组识别区域，每组区域独立识别、独立翻译，并在对应区域附近显示翻译结果。

项目目标不是做通用翻译平台，而是做一个稳定、轻量、低干扰、适合学习与文字内容场景的辅助翻译工具。

## 3. 产品目标

### 3.1 核心目标

- 支持通过鼠标框选屏幕上的固定字幕或文本区域
- 支持持续识别该区域中的内容变化
- 支持将 OCR 结果发送到联网 AI 接口进行翻译
- 支持将翻译结果显示在选区附近的悬浮窗中
- 支持最多 3 组独立的“选择框 + 翻译窗”同时工作
- 支持每组独立设置源语言与目标语言
- 在正常网络环境下，首条翻译与后续刷新大多数情况控制在 4 秒内

### 3.2 体验目标

- 低干扰：平时仅显示必要边框与翻译结果，不影响观看内容
- 快速上手：通过快捷键即可新建和编辑
- 配置清晰：通过 GUI 配置 AI 接口、模型和全局提示词
- 稳定优先：优先保证结果稳定与交互清晰，而非功能堆叠

## 4. 非目标范围

以下内容不属于第一版范围：

- 自动语言识别
- 历史记录或字幕回放
- 退出后恢复上一次的 3 组选区状态
- 字幕位置自动跟随
- 选区边框自由拉伸微调
- 多平台支持
- 本地离线大模型翻译

## 5. 目标用户与使用场景

### 5.1 目标用户

- 在直播课、录播课、翻译题和阅读任务中需要辅助理解外语内容的用户
- 在文字游戏、跑团、视觉小说、国外游戏中需要即时辅助翻译的用户
- 希望自行配置 AI 接口和提示词的用户

### 5.2 典型场景

- 用户在播放器、浏览器、PDF 阅读器或任意桌面窗口中观看带有外语内容的区域
- 用户按快捷键创建框选区域
- 软件持续识别区域中的文本，并将翻译结果显示在选区附近
- 用户在编辑模式下调整语言对、位置、暂停状态或删除某一组

## 6. 名词定义

- 选择框：用户框选的固定屏幕识别区域
- 翻译窗：显示某一组翻译结果的悬浮窗口
- 组：一对“选择框 + 翻译窗”及其对应状态
- 普通模式：观看态，仅显示低干扰边框与翻译结果
- 编辑模式：可编辑态，支持修改区域、拖动翻译窗和切换语言
- 固定模板层：系统内置、最高优先级、不可缺失的 Prompt 基础模板
- 约束层：用户手动输入的翻译约束内容
- 知识引用层：用户提供的本地知识文档引用，用于术语、风格和固定表达约束
- Compiled Prompt：由系统根据三层 Prompt 架构生成并保存到本地的最终运行提示词

## 7. 产品结构

产品由以下几个部分组成：

- 主程序进程
- 系统托盘入口
- GUI 配置窗口
- 全局快捷键模块
- 选择框悬浮层
- 翻译窗悬浮层
- OCR 识别模块
- AI 翻译模块
- 状态管理与任务调度模块

## 8. 功能需求

### 8.1 程序运行与生命周期

- 软件以 Windows 桌面程序形式运行
- 软件启动后可常驻系统托盘
- 关闭主 GUI 窗口时程序不退出
- 托盘菜单至少包含以下功能：
  - 打开设置
  - 全部显示 / 全部隐藏
  - 退出程序
- 第一版默认不开机自启

### 8.2 GUI 配置窗口

GUI 用于集中管理全局配置，不承担实时翻译主交互。

GUI 至少包含以下配置区：

- 通用设置
- AI 配置
- Prompt 配置

AI 配置项至少包括：

- Base URL
- API Key
- Model

Prompt 配置要求如下：

- Prompt 系统采用三层结构：
  - 固定模板层
  - 约束层
  - 知识引用层
- 固定模板层由系统内置并保持最高优先级
- 即使用户不填写约束层和知识引用层，固定模板层也必须保证 Prompt 完整可用
- 约束层由用户手动输入
- 知识引用层由用户提供本地文档路径，文档格式以 Markdown 为主
- 所有 3 组共享同一套 Prompt 系统配置
- 最终用于翻译的不是原始三层输入，而是生成后的 `compiled prompt`
- `compiled prompt` 以文件形式保存在用户本地电脑中
- 用户必须先预览编译结果，再确认保存并启用 `compiled prompt`

GUI 还需支持以下管理动作：

- 新建选择框
- 全部隐藏 / 全部显示
- 查看当前已创建组的基本状态
- 生成 Prompt 预览
- 确认保存并启用 `compiled prompt`

### 8.3 全局快捷键

软件需支持以下默认全局快捷键：

- `Ctrl + Shift + Z`：新建选择框
- `Ctrl + Shift + X`：切换编辑模式

快捷键行为要求如下：

- 触发新建时，若当前未达到 3 组上限，则进入框选流程
- 若已达到 3 组上限，则提示用户当前无法继续新建
- 编辑模式为全局切换，进入后 3 组同时处于可编辑状态
- 再次按下编辑快捷键后退出编辑模式

### 8.4 组数量与独立状态

- 软件最多支持 3 组同时存在
- 每组必须具备独立状态，至少包括：
  - 选区坐标
  - 翻译窗位置
  - 源语言
  - 目标语言
  - 当前 OCR 文本
  - 当前翻译结果
  - 当前工作状态

### 8.5 选择框

#### 8.5.1 创建流程

- 用户通过快捷键或 GUI 触发新建
- 进入框选流程后，用户使用鼠标框出屏幕中的字幕或文本区域
- 选区创建完成后，立即进入该组的持续识别状态

#### 8.5.2 显示要求

- 普通模式下，仅显示简洁、低干扰的边框
- 边框需要可区分不同组，但视觉风格应克制，不影响内容观看
- 每组使用“编号 + 低饱和颜色”进行标识
- 推荐样式为细边框 + 小号编号角标

#### 8.5.3 编辑要求

- 第一版不支持通过拖拽边框微调大小
- 调整选区时，使用“重选区域”方式整体重新框选

### 8.6 编辑模式与工具条

- 编辑模式下，3 组同时进入可编辑状态
- 鼠标移入某一组选择框时，显示该组的悬浮工具条
- 鼠标未聚焦时，工具条隐藏
- 工具条风格参考轻量悬浮操作条，强调低干扰与直观性

每组工具条至少支持以下动作：

- 重选区域
- 暂停 / 继续
- 删除该组
- 源语言切换
- 目标语言切换
- 交换源语言与目标语言
- 调整翻译窗停靠方向（上 / 下 / 左 / 右）

### 8.7 翻译窗

#### 8.7.1 基本展示

- 每组必须有对应翻译窗
- 翻译窗默认只显示翻译结果
- 翻译窗顶部显示当前语言对，例如：`English => 中文`
- 翻译窗需显示简洁状态信息，例如：
  - 识别中
  - 翻译中
  - 仍在翻译...
  - 未识别到文本

#### 8.7.2 位置与布局

- 翻译窗默认停靠在选择框下方
- 若下方空间不足，则自动尝试放置到上方
- 左右方向亦应具备基础越界避让能力
- 用户可通过工具条一键切换翻译窗停靠方向：
  - 上
  - 下
  - 左
  - 右
- 用户可直接拖动翻译窗位置

#### 8.7.3 大小要求

- 翻译窗宽度固定
- 翻译窗高度随内容自动变化
- 第一版不支持用户手动拉伸翻译窗尺寸

### 8.8 语言设置

每组独立支持以下语言设置：

- 源语言：中文 / 日本語 / English
- 目标语言：中文 / 日本語 / English

功能要求如下：

- 每组源语言与目标语言相互独立
- 支持在翻译窗或工具条中快速切换语言对
- 支持一键交换源语言与目标语言
- 第一版不支持“自动识别”选项

### 8.9 OCR 识别流程

OCR 流程要求如下：

- OCR 在本地执行
- 软件对每组区域进行低频巡检
- 巡检频率推荐为每 500 ms 一次
- 若检测到区域内容变化，则触发 OCR
- OCR 语言按用户设置的源语言执行，不使用自动混合识别

为提升稳定性，OCR 模块需支持以下优化策略：

- 灰度化
- 对比度增强
- 必要时二值化
- 适当裁剪无效空白区域
- 文本有效性过滤
- 相似度去重
- 稳定确认机制

稳定确认机制要求如下：

- 对识别结果进行相似度判断
- 若新结果与上一条高度一致，则不重复触发翻译
- 对明显无效、乱码或纯符号结果，不发送 AI 翻译请求

### 8.10 AI 翻译流程

AI 翻译流程要求如下：

- 仅将 OCR 提取后的文本发送到联网 AI 接口
- 不直接发送截图给 AI 作为第一版默认流程
- AI 响应应只返回翻译结果
- 不需要解释、总结、润色或扩写
- 翻译请求必须使用本地已确认保存的 `compiled prompt`

Prompt 约束要求如下：

- 固定模板层优先级最高，其次为约束层，再次为知识引用层
- 约束层和知识引用层允许为空
- 知识引用层中的文档内容不得整篇原样直接参与运行时翻译
- 知识引用层应先提炼为“术语表 + 风格规则 + 固定表达”等结构化信息，再参与编译
- Prompt 编译只在配置变更后进行，不允许在每次翻译时重复编译
- Prompt 编译完成后，用户必须确认预览结果，系统才可写入并启用新的 `compiled prompt`

### 8.11 刷新与任务策略

为兼顾时效性与稳定性，任务调度需满足以下规则：

- 新字幕或新文本出现时，优先处理最新内容
- 若上一条 AI 请求尚未返回，则继续等待其返回
- 队列中仅保留“最新一条待翻译项”，不无限累积中间项
- 已过期的翻译结果返回后，不得覆盖当前最新内容的结果

### 8.12 暂停、删除与显示控制

每组需支持以下管理动作：

- 暂停识别
- 恢复识别
- 删除该组

全局需支持以下动作：

- 全部隐藏
- 全部显示

“全部隐藏 / 全部显示”功能可放在 GUI 或系统托盘中。

## 9. 性能需求

### 9.1 响应时间目标

在正常网络环境下：

- 首条翻译出现：大多数情况不超过 4 秒
- 后续内容变化刷新：大多数情况不超过 4 秒

### 9.2 说明

- 该指标为项目目标，不要求在所有极端网络情况下绝对满足
- 若超过 4 秒，系统继续等待结果返回，不主动取消本次请求
- UI 需持续显示处理中状态，避免用户误认为程序卡死

## 10. 异常处理

### 10.1 OCR 失败

若 OCR 未识别到有效文本或结果明显异常：

- 保留上一条翻译结果
- 在翻译窗显示“未识别到文本”或“识别中”
- 不发送低质量 OCR 结果到 AI

### 10.2 AI 响应慢

若 AI 响应超过 4 秒：

- 继续等待
- 翻译窗显示“仍在翻译...”
- 不清空当前已有翻译

### 10.3 结果过期

若旧请求结果返回时，当前内容已变化：

- 丢弃该结果
- 不覆盖当前显示结果

## 11. 数据与持久化策略

### 11.1 保留内容

程序运行过程中可保留临时状态：

- 当前 3 组配置
- 当前 OCR 文本
- 当前翻译结果
- 临时运行日志

### 11.2 不保留内容

程序退出后不保留以下内容：

- 选择框坐标
- 翻译窗位置
- 每组语言设置
- 当前翻译内容

### 11.3 可保留的全局配置

建议保留以下全局配置，便于用户重复使用：

- Base URL
- API Key
- Model
- 约束层输入内容
- 知识引用层文档列表
- 当前启用的 `compiled prompt`
- 快捷键配置（如后续支持）

## 12. 界面风格要求

- 整体风格应简洁、克制、工具化
- 不使用高饱和、夸张或过度花哨的装饰
- 选择框与翻译窗的标识应低干扰，但能快速区分 1 / 2 / 3 组
- 编辑态与普通态需有明确区别，但不能影响用户观看体验
