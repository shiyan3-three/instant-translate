## 二、核心问题

**每次翻译都是一次全新的 API 调用。规则（200-1600 字）每次都重新发送，模型每次都重新消化。** 导致：

| 场景 | 耗时 | 结果 |
|------|------|------|
| 无规则 flash 关思考 | 1.0s | ✅ |
| 有规则 flash 关思考 | 1.7s | ❌ 字符级约束不服从 |
| 有规则 flash 开思考 | 5.7s | ⚠️ 太慢 |

**根因**：约束层、引用层、固定模板混在一起，全部塞给一个 API 调用。复杂约束需要推理能力，但推理模型不能每翻一句都思考一次。

## 三、Agent 化方案

### 核心思路

不是"编译规则的工具"，而是**有记忆、能自主决策的在线翻译助手**。

```
┌─────────────────────────────────────────────┐
│                   Agent                        │
│                                               │
│  启动时（一次性）:                               │
│    规则 + 引用层 → thinking 模型消化              │
│    → 规则进入上下文（KV cache）+ reasoning_content │
│    ← 慢一次（≈5-10s）                           │
│                                               │
│  翻译时（每次）:                                  │
│    原文 → 模型直接翻译（规则已在上下文中）            │
│    ← 1-2s，思考模型也能秒回                        │
└─────────────────────────────────────────────┘
```

### 关键洞察

DeepSeek 网页测试发现：**thinking 模型先思考一次，之后切到非思考模式，正确度也会提高。** 因为前一条消息的 `reasoning_content`（内部推理链）留在上下文里，后续模型读到它就"知道"了规则意图。

```
第0轮: thinking=enabled  → 模型输出 reasoning_content + "已理解规则"
第1轮: thinking=disabled → 模型读上下文中的推理链 → 直接翻译 → 1s 且正确
```

### 引用层处理

两份并行：
- **术语索引**：拆成 KV 字典（`{"DB":"数据库", "Click":"点击"}`），翻译前扫原文，命中直接替，不走 API
- **上下文搜索**：未命中的，按原文关键词搜引用层文档，只发相关片段

### 上下文管理

- **短期记忆**：翻译对 + OCR 原文 + 用户修正 → 保持术语一致
- **长期记忆**：用户手动修正过的翻译 → 存 `memory.json` → 下次自动采用
- **溢出策略**：Windsurf 风格本地存储 + Cursor 风格 compact 压缩：
  - 日常存本地 JSON
  - 窗口快满时，旧条目 compact 成摘要段落嵌入上下文
  - 不丢信息，不爆窗口

### 工具栏加"反馈修正"按钮

编辑模式下新增按钮 → 弹窗让用户输入正确译文 → Agent 更新记忆。

## 四、GUI 重构：翻译模板

### 三个功能合并为一个

```
翻译模板 = 语言方向 + 提示词配置 + 会话管理

一个模板 = 一个完整的翻译场景
  例: "游戏日语翻译"
    = 日→中 + 平假名约束 + 游戏术语引用层 + 该场景的翻译记忆
```

### 侧边栏变化

```
  之前（四页）              之后（三页）
  ┌──────────┐             ┌──────────┐
  │ 翻译方向  │             │          │
  │ 模型配置  │    →        │ 翻译模板  │ ← 合并
  │ 提示词    │             │ 模型配置  │
  │ 设置      │             │ 设置      │
  └──────────┘             └──────────┘
```

### 翻译模板页布局

```
左侧：模板列表
  ├── "游戏日语翻译"
  ├── "课堂英文翻译"
  ├── "默认"
  └── [+ 新建模板]

右侧：选中模板详情
  ├── 语言方向：源 [English ▼] → 目标 [中文 ▼]
  ├── 约束层：[点击编辑...] 按钮 → 弹窗
  ├── 引用层：文档列表 + 添加/移除
  ├── 编译预览 + 保存并启用
  └── 当前记忆：N 条翻译记录
```

## 七、POC 验证结果（2026-06-11）

**测试结论**：全程开 thinking，后续推理量自然衰减。不需要快慢模型切换。

| 轮次 | 耗时 | reasoning_tokens | 结果 |
|------|------|:---:|------|
| 第1轮(消化规则) | 2.3s | 128 | 确认理解 |
| 第2轮(翻译) | 1.5s | 38 | HELLO WORLD ✅ |
| 第3轮(翻译) | 1.6s | 24 | GOOD MORNING ✅ |
| 第4轮(翻译) | 1.4s | 32 | THANK YOU VERY MUCH ✅ |
| 第5轮(翻译) | 1.4s | 59 | HOW ARE YOU TODAY ✅ |

**修正后的 Agent 模式**：不是"先思考后关"，而是**全程开 thinking，持有一个 messages 会话**。KV cache 复用使后续推理成本大幅降低（128→24-59 tokens）。

**被否决的方案**：先消化→关 thinking。理由：POC 证实 reasoning_content 不传递到非 thinking 轮次。
