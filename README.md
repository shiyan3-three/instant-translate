# instant-translate

一个面向学习和文字内容场景的 Windows 即时辅助翻译悬浮工具。

它的目标不是做一个大而全的翻译平台，而是在你正在看直播课、做翻译题、玩文字游戏、跑团或阅读外语屏幕内容时，提供一种**不切窗口、不打断当前操作、低干扰显示结果**的即时辅助翻译体验。

## 这个项目解决什么问题

市面上很多翻译软件的问题不是不能翻，而是：

- 需要切到别的窗口或弹出独立大面板
- 会遮住播放器、游戏或文本内容
- 操作链条长，影响节奏
- 更适合通用翻译，不够适合“我就想马上看懂这一小块内容”

本项目针对的是更具体的场景：

- 直播课中遇到不会翻的句子，想马上辅助理解
- 外语学习中卡在一段字幕或文本上，想先看一眼翻译再继续
- 文字游戏、跑团、视觉小说、国外游戏中，想避免一按翻译键就把游戏窗口打断

## 核心思路

- 用户用快捷键创建字幕或文本识别区域
- 软件持续识别该固定区域中的内容变化
- 先在本地做 OCR，再把文本交给 AI 翻译
- 翻译请求不直接使用用户原始输入，而是使用三层 Prompt 架构编译出的 `compiled prompt`
- 翻译结果以悬浮窗形式显示在区域附近
- 最多支持 3 组独立区域同时工作

## 为什么依赖 AI

本项目依赖 AI，但不把 AI 放在最前面看图。

原因很简单：

- 直接把截图发给 AI 看图翻译，成本更高、速度更慢、波动更大
- 先本地 OCR，再把纯文本发给 AI，通常更快、更稳，也更容易控制结果格式

因此本项目的默认架构是：

`屏幕区域 -> 本地 OCR -> 文本清洗 -> compiled prompt + AI 翻译 -> 悬浮结果展示`

## 当前代码骨架

项目已经预留了 `app/` 目录骨架，后续实现会围绕以下模块展开：

- `gui/`：设置窗口、主窗口、托盘入口
- `overlay/`：选择框、翻译窗、编辑模式控制
- `capture/`：屏幕截图与变化检测
- `ocr/`：图像预处理与 OCR 调用
- `prompt/`：三层 Prompt 架构、编译与本地保存
- `translation/`：OpenAI 兼容接口调用与翻译服务
- `state/`：多组状态建模与运行时存储

## 项目边界

第一版明确不做这些内容：

- 自动语言识别
- 历史记录
- 音频转字幕
- 多平台支持
- 本地离线大模型翻译
- 大而全的翻译工作流

## 设计原则

- 不打断优先：不能因为翻译打断主任务
- 低干扰优先：平时安静，只在需要时暴露控制能力
- 稳定优先：先确保可用，再追求复杂功能
- 速度优先：目标是在正常网络环境下大多数场景 4 秒内出结果
- 轻量优先：聚焦学习与文字内容场景，不做功能堆叠
