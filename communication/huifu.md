## 逐条回应

### 问题 1：Agent 化方向

三个风险他都点到了：

- **风险 A（thinking 切换可靠性）**：同意，必须 POC 验证。这是整个 Agent 方案的前置条件
- **风险 B（上下文窗口管理）**：同意需要降级策略。但他说"压缩算法需要调 API"——不一定。compact 可以是纯客户端操作：保留术语 KV + 最近 N 轮对话 + 旧翻译摘要（纯文本拼接），不调 API
- **风险 C（用户反馈回路）**：他提的 ✓/✗ 快速反馈按钮比我们想的工具栏弹窗更轻量。翻译窗上加两个小按钮不破坏现有交互。值得采用

**他提议的替代方案不成立**：

> "不关 thinking，在 system prompt 里注入'规则已在前文消化，直接应用'"

没有意义。不关 thinking 每条都得重新推理，慢的问题根本没解决。他就是对关 thinking 不放心，提的替代方案不能解决核心矛盾。

他提的"两个独立 Agent"也多余——规则消化和翻译执行本就是同一个会话的不同阶段，不需要拆。

### 问题 2：DeepSeek thinking 切换

验证方案他写得比我们详细——三个 POC 场景 + 潜在坑点 + 实测方法。直接拿来用。

**他提到的"计费问题"很重要，我们之前没讨论过**：消化一次消耗多少 thinking tokens？成本能不能接受？需要 POC 时一并看 `usage.reasoning_tokens`。

### 问题 3：OCR 卡死

他说"50% PaddleOCR 问题、50% 去重逻辑问题"——这个比例是他猜的，加完日志才知道。但他提的定位方法和修复方向都靠谱：

**可以采用的**：
- 入口/出口加时间戳日志判断卡在哪一侧
- 大段文本降采样（resize 到 max_width=1920）
- 超时保护：OCR 超过 5s 强制返回空结果
- **"只对比最后 200 字"**——字幕变化通常是底部新增，这个判断准确

**需要斟酌的**：
- "每 100 次识别后重新初始化 PaddleOCR"——太暴力，可能引入新的延迟问题。应该先确认是不是真的需要重置

### 问题 4：编辑模式闪烁

他给了三个方案，判断准确：

- **方案 A（状态比对+脏标记）✅ 采纳**：干净，改动小，治本
- **方案 B（工具栏状态记忆）**：辅助手段，可以和 A 组合
- **方案 C（防抖）❌ 不采用**：治标，治不了 500ms 的持续重绘

### 问题 5：优先级

和我们自己的判断完全一致：

```
🔴 闪烁 > OCR诊断 > thinking验证
🟡 术语索引 > OCR预热 > 翻译方向持久化
```

## 还想追问他的

### 1. 翻译模板重构没被提到

我们的计划里有一个重要的 GUI 改动——把侧边栏从四页改为三页，"翻译模板"合并语言方向+提示词+会话管理。这个改动不小。他没提，可能没注意到。想问他：**这个合并方案有没有更好的 UI 组织方式？**

### 2. 为什么"两个独立 Agent"不可行（他没理解到位）

他提的备选方案"两个独立 Agent：一个消化规则，一个执行翻译"。这其实回到了我们正在逃离的模式——执行翻译的 Agent 没有规则在上下文里，规则必须通过 system prompt 传过去，等于每次翻译又得重发规则。Agent 化的核心价值就是"规则只发一次"，拆成两个等于丢掉这个价值。

### 3. compact 不一定需要调 API（他可能想复杂了）

他说"压缩算法本身需要调 API"。不一定——compact 可以是纯客户端操作：保留术语 KV 索引 + 最近 N 轮原文/译文对 + 把更早的翻译压缩成一句摘要文本。这只是字符串操作，不需要调模型。

### 4. 每 100 次重置 PaddleOCR 的问题

他没考虑到重置的代价——重新加载模型可能又要好几秒，比卡死还糟糕。应该先加日志确认是不是 PaddleOCR 内部问题，如果是再考虑周期性后台预热式的"软重置"，而不是简单暴力的 `del engine; engine = PaddleOCR()`。

## 已完成：任务 1-3（2026-06-11）

### 1. 编辑模式闪烁 ✅

**方案**：方案 A（状态比对 + 脏标记）。

`SelectionBoxWidget.apply_model` 新增 `_last_applied_state` 缓存。每次调用比较当前 state（坐标、尺寸、组号、颜色、暂停、语言对、编辑态），不变就 `return` 跳过重绘。工具栏不再每 500ms 闪烁。

**文件**：`app/overlay/selection_box.py`

### 2. OCR 日志 ✅

`OcrEngine.recognise` 入口/出口加时间戳日志：

```
[OCR-IN]  lang=English size=320x96
[OCR-OUT] lang=English prep=3ms total=350ms len=42 text='hello...'
```

如果 `[OCR-IN]` 出现但 `[OCR-OUT]` 不出现 → PaddleOCR 内部卡死。如果 `[OCR-OUT]` 出现但翻译窗不更新 → 去重误杀。

**文件**：`app/ocr/engine.py`

### 3. 翻译方向持久化 ✅

`AppSettings` 新增 `default_source_language` / `default_target_language` 字段，`load()`/`save()` 覆盖。`LanguagePage` 启动时从 settings 读默认值，`_on_language_changed` 调 `settings.save()` 写盘。

**文件**：`app/settings.py`、`app/gui/main_window.py`

### 附带修复

`_compact_compiled_prompt` 简化——去掉 `capture` 状态机，直接跳过 `#`/`##` 标题行和 `This layer` 描述行，保留所有内容。解决了没有 markdown 标题的编译提示词被完整丢弃的问题。

**文件**：`app/translation/service.py`
