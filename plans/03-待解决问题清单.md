## 🔴 阻塞级（必须先解决才能推进）

### 0. 编辑模式下选择框闪烁（NEW）
- **问题**：编辑模式下，选择框的尺寸 badge、组号、工具栏不断闪烁，导致工具栏按钮点不到
- **根因分析**：每 500ms 的 OCR 轮询触发了选择框的重绘（`_upsert_selection_box` 或 `apply_model` 反复调用），工具栏被反复 show/hide
- **修复方向**：`_upsert_selection_box` 只在几何/语言真正变化时才调用 `apply_model`，避免每轮轮询都触发 show()；或给工具栏加防抖
- **状态**：❌ 未修复

### 1. 选择框内文字过多时 OCR 卡死（NEW）
- **问题**：选择框内文字较少时正常。但如果框内文字很多（大段文本），运行一段时间后，文字变化了 OCR 仍显示旧结果，不更新
- **根因分析**：可能是 PaddleOCR 在处理大面积文本图像时内部状态累积；或长时间运行后 `_last_logged_ocr` 的旧文本与变化后的新文本相似度过高（大量文本中只有少量变化时 trigram 相似度仍然很高），被误判为重复跳过
- **修复方向**：检查长时间运行后 PaddleOCR 实例是否需要周期性重置；考虑对大段文本降低相似度判断的阈值或改用编辑距离算法；确认变化检测触发后是否真正清了 OCR 去重缓存
- **状态**：❌ 未修复

### 2. DeepSeek API thinking 切换验证

### 1. DeepSeek API thinking 切换验证 ✅ 已验证
- **结论**：thinking=disabled 无法复用前轮 reasoning_content（POC 证实）。但发现更优方案：**全程开 thinking，后续推理量自然衰减**（首轮 128 tokens → 后续 24-59 tokens，耗时 1.4-1.6s）
- **Agent 方案修正**：不是"先思考后关"，而是"全程思考，持有一个 messages 会话，KV cache 复用使推理成本大幅降低"
- **状态**：✅ 验证通过，Agent 方案可行
